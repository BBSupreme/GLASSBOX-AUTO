# Run an offer check

This guide covers conditional calculations from user-supplied Danish new-car
private-leasing terms. It does not enable the separate full-ranking design,
purchase economics or live offer verification.

## Capability check

You need repository files, a local directory and Python process execution.
A browser-only assistant may prepare inputs but must report **UNEXECUTED**. Do
not treat an AI product name as a capability guarantee. No named provider
compatibility is asserted by this guide.

Read [AGENTS.md](../AGENTS.md). Pin one commit for instructions, schemas and code.
Record `git rev-parse HEAD`, `python --version` and
`python -m glassbox_auto.cli --version`.

## Try the synthetic example

```bash
git clone https://github.com/BBSupreme/GLASSBOX-AUTO.git
cd GLASSBOX-AUTO
python -m venv .venv
```

Activate with `source .venv/bin/activate` on macOS/Linux or
`.venv\Scripts\Activate.ps1` in Windows PowerShell. Then:

```bash
python -m pip install .
python -m glassbox_auto.cli example
```

`example` prints a bundled fictional draft. From the cloned repository, prepare
that same fixture:

```bash
python -m glassbox_auto.cli prepare src/glassbox_auto/examples/complete.json --output demo-prepared.json
```

Read `demo-prepared.json`. It contains `status: "AWAITING_CONFIRMATION"`, a
`request_sha256` and the normalized `request`. This fixture is fictional; confirm
that these are the synthetic inputs you intend to demonstrate.

Copy the normalized `request` object to `demo-request.json` and add the field:

```json
"confirmation": {
  "request_sha256": "the actual digest returned by prepare"
}
```

This is a field inside the request object, not the complete file. Replace the
placeholder with the actual digest. Do not use the outer prepare-response
object as the request. An assistant can perform these file steps after you
confirm the displayed inputs. Then:

```bash
python -m glassbox_auto.cli assess demo-request.json --output demo-result.json
```

For this fictional example, expect DKK 141,600 over 36 months, an average of
DKK 3,933.33 per month, and recurring rent plus entered insurance of DKK 4,000.
Initial non-monthly cash is DKK 15,000, excluding the first regular instalment.
The source remains `UNVERIFIED` and recommendation `NOT_ASSESSED`. These are
different measures: do not label the average as the recurring bill.

The `--output` examples require POSIX filesystem primitives (as on the tested
Linux environment). On Windows or a platform without those primitives, omit
`--output`, read the JSON from stdout and save the prepared request in a text
editor. No Windows execution certification is claimed. Every output path must
be new. Omitting `--output` prints successful JSON to
standard output. Errors use standard error and a nonzero exit code; do not read
an old result as evidence of a failed new run.

Other bundled cases are [incomplete](../src/glassbox_auto/examples/incomplete.json)
and [over-mileage](../src/glassbox_auto/examples/over-mileage.json), also accessible
with `example --name incomplete` and `example --name over-mileage`. Use the same prepare,
review, confirm and assess sequence with fresh output names. They demonstrate
incomplete information and mileage scenarios, not live market prices.

## Check your own quote

1. Collect exact configuration and dated terms. Preserve wording about included
   payments, fees, deposits and mileage. An omitted charge is not zero.
   Use VAT-inclusive consumer prices for private operating leases. Business
   ex-VAT prices, financial/flexleasing and residual-value liabilities are outside
   the interface; do not silently normalize them into a supported quote.
2. Build the request using the [contract](OFFER_CHECK_CONTRACT_v1.md). Use `null`
   for permitted unknowns. Do not add undocumented fields or evidence grades.
3. Run `prepare`. Show the complete normalized request plus a readable summary,
   including fixed assessment time, sources, dates, budget basis and unknowns.
   For multiple offers, keep term and mileage alongside each price.
4. Obtain confirmation of that request. Any profile, offer, source, policy or
   assessment-time change requires fresh preparation and confirmation.
5. Add the returned confirmation digest, run `assess` to a fresh output and check
   the exit code before opening it.
6. Check output code/policy/schema identity and normalized request digest. Retain
   the command, exit code and decision digest. Explain what was calculated and
   what remains unknown.

The entire normalized request except `confirmation` is fingerprinted. The hash
can be generated by anyone: the actual confirmation belongs in the conversation.
It neither authenticates consent nor proves source truth.

## Interpret the result

| Output concept | Interpretation |
|---|---|
| `CALCULATED_FROM_INPUTS` | Required arithmetic was possible from the supplied numbers |
| `INCOMPLETE_INPUTS` | Some required inputs are unknown |
| `WITHIN_ENTERED_LIMIT` / `EXCEEDS_ENTERED_LIMIT` | Comparison against the declared cost basis, not affordability |
| `UNKNOWN` / `NOT_REQUESTED` budget outcome | Insufficient input or no limit requested |
| `source_verification: UNVERIFIED` | Supplied source claims have not been authenticated |
| `recommendation: NOT_ASSESSED` | The checker has not recommended a vehicle or contract |

The nonrefundable contract total excludes refundable deposit and incremental
insurance. The recurring monthly-budget check includes incremental insurance
only with `LEASE_AND_INSURANCE`. Unknown fees prevent a complete contract total.
No under-mileage refund is assumed.

**Initial non-monthly cash excludes the first regular monthly payment.**
`max_initial_non_monthly_dkk` checks the initial payment + fees due initially +
refundable deposit. Add the first regular payment separately for day-one cash
planning, and check when insurance is due. A monthly average is different from a recurring bill. Keep commitment
period and mileage visible when comparing averages.

The offline engine does not visit URLs or confirm availability. A recent
observation does not override stated expiry. Conflicting terms need resolution;
never select whichever terms produce the cheapest result. Running costs, return
condition, suitability, safety and contract interpretation remain separate work.

## Determinism and failures

The result separates deterministic `decision`, its `decision_payload_sha256`,
and raw-input `transport` provenance. Formatting can change the raw digest
without changing the normalized request or decision. A new assessment date is a
changed input. Hashes are not signed execution attestations.

| Exit | Meaning | Next action |
|---|---|---|
| 0 | Assessment completed, possibly with unknowns or exceeded limits | Read limitations; this is not a recommendation |
| 2 | Invalid input, confirmation, command or file usage | Correct it; prepare again after input changes |
| 3 | Unsupported acquisition method | Do not relabel a purchase as a lease |
| 4 | Internal, deadline or output-publication failure | Discard stale output; retain a sanitized reproducer |
| 5 | Empty offer set | Supply an offer |
| 6 | Unsupported/incompatible currency | Use DKK offers; no implicit conversion |

The [contract](OFFER_CHECK_CONTRACT_v1.md) defines exact precedence and limits.
Inputs are rejected explicitly rather than silently truncated or repaired.

The evaluator uploads nothing. Your AI host may process material you give it
under its own terms. Remove private details before sharing a quote or reporting
a bug. Never commit actual household data.
